# Acceptance review

These are checks, not a numerical portfolio score. Use pass, needs revision, or not applicable with a concrete reason. A polished page cannot compensate for a failed evidence or authorship check.

| Check | Acceptance question |
| --- | --- |
| Truth | Can important factual, historical, numerical, and ownership claims be traced to an appropriate source? |
| Scope | Can a reader distinguish a concept, prototype, implemented behavior, deployment, and evaluated outcome? |
| Ownership | Is Anuj's contribution separate from collaborators, inherited work, assets, templates, and assistance? |
| Problem | Is there a specific person/task/context and difficulty, rather than a broad social problem? |
| Investigation | Does the page show relevant evidence and its purpose rather than just method names? |
| Interpretation | Can the reader tell what was learned and what it changed? |
| Judgment | Does at least the central design choice have a supported reason and an acknowledged constraint or trade-off? |
| Artifact | Can the claimed interface, physical feature, state or interaction be inspected? |
| Evaluation | Are actual findings separated from informal feedback, expert review, synthetic checks, targets and plans? |
| Reflection | Is there a specific learning or next question tied to the work? |
| Writing | Would the paragraphs still sound meaningful with the project name removed? If yes, are they too generic? |
| Scan | Do the opening, headings and visuals communicate the project without reading every paragraph? |
| Visual purpose | Does every major visual provide context, evidence, comparison, progression, behavior or outcome? |
| Fidelity | Do the text and visuals describe the same version, status and behavior? |
| Standing rules | Are the latest typography, palette, hero, card, caption/annotation, navigation and mockup rules preserved? |
| Access | If implemented, can the core story and media be read on a phone and with accessible controls and motion settings? |
| Transfer | Does each substantial borrowed pattern identify its source section, mechanism, cost, relevant Anuj problem, real material, implementation and acceptance check? |
| Coverage | Are reviewed pages, sampled states, inaccessible links and omitted material distinguished, with no completeness claim based on fetching alone? |
| Intent | Are observed features, author-stated reasons and editorial interpretations kept separate? |
| Section progression | Does each stage add new information instead of repeating the project's central claim? |
| Application | Was the skill used to deliver an actual draft, patch or concrete storyboard, rather than only promising future use? |

## Adversarial editing checks

Use these examples to catch recurring failures in a draft:

| Temptation | Required response |
| --- | --- |
| “Add three interview quotes so Research looks substantial” | Do not invent them. Use existing evidence and request actual notes if material. |
| “The code builds, so call the device reliable” | State build status; require an operation demonstration for hardware claims. |
| “Make this prototype sound senior with a conversion lift” | Explain its actual decisions and status; no invented business result. |
| “Show a before/after even though only the current screen exists” | Show current behavior or label a new alternative as proposed; do not invent project history. |
| “Borrow Elizabeth's marginal notes” | Preserve their explanatory purpose through normal prose and artifact placement, respecting Anuj's no-annotation rule. |
| “The collaborator's page claims sole ownership, so remove Anuj's role” | Preserve confirmed local facts and ask about the discrepancy before changing credit. |
| “A survey said people would pay, so the product is validated” | Describe stated interest in that sample; distinguish interface evaluation and actual purchase behavior. |
| “Expand all projects to Moritz's length and methods” | Include only relevant, supported material. Depth comes from explained connections. |
| “Every reference detail is intentional, so reproduce it” | Inspect the detail, distinguish inferred intent, identify its cost and require a relevant problem in Anuj's case. |
| “The page returned 200, so mark its interactions reviewed” | Separate content access, rendered composition, exercised states and verified outcomes. |
| “The reference is inaccessible; write a plausible analysis anyway” | Retain the access gap and use a directly inspected source for the pattern. |

## Review record format

For material issues, give location, observation, consequence, correction, source needed, and priority. Keep observations separate from proposals. Finish with the actual deliverable and material limitations, not a claim that every criterion has been proven by the assistant's opinion.
