The editorial standard connects a specific situation, evidence, interpretation, decision/trade-off, artifact/behavior and actual evaluation or status. It does not require every project to have performed the same research process.

References guide explanation and composition. They do not supply Anuj's project facts, override standing presentation rules, establish verified impact, or authorize publication. Case content and the live site were not changed to create this skill.

The expanded review inventories all five internally hosted cases on Sukhman's project index, the Drive Wise and My Alumnus full cases, three linked research reports and all nine public case pages on Neha's portfolio. It also examines the other named designers where accessible. Thirty-nine distinct external page captures and four Anuj page captures support the review; captures are not equivalent to complete interaction audits. Simon's Uber case, the current believr Figma contents and three relevant Behance cases remain inaccessible. The ledger records those gaps rather than treating secondary descriptions as direct observations.

The skill has been applied to the current repository content, yielding concrete refinements for Meditimer, Himalayan, Toki, India in Orbit, roundabouts, Swiggy, physical Meditimer and My Alumnus. The copy drafts consolidate supported facts; they do not invent missing project history. The next implementation pass can use these plans without repeating the reference survey.

Example:

> Use $portfolio-case-study-editorial to implement the Himalayan copy consolidation and visual plan. Recheck the current prototype states, preserve the original survey scope and credits, and use only real state captures. Keep unresolved historical alternatives as a source question.
